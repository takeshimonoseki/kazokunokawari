# フォーム連携設計書 (GAS - Google Sheets)

## 目的
カゾクノカワリの問い合わせ・依頼フォームを、将来的にGAS経由でGoogle Sheetsへ保存し、管理者通知と必要に応じた自動返信を行うための設計。

## 現時点の方針
- まずは設計のみ
- 実装は別タスク
- APIキー、GAS URL、Spreadsheet IDはHTMLに直書きしない
- Google Maps API、GAS、Sheets連携は外部連携のため、明確な依頼後に実装
- 本番送信テストは事前確認後のみ行う
- GAS URL、Spreadsheet ID、APIキー等は公開HTML/JSやdocsに実値を書かず、Script Properties等で管理する。

## 参考にする既存方式
既存HPの方式を抽象化すると、以下の通り。
- フロントエンド (HTML/JavaScript) からGoogle Apps Script (GAS) Web AppへフォームデータをJSON形式でPOST送信する。
- GAS側で受信したJSONデータをパースし、指定のGoogle Sheets (スプレッドシート) へ行として保存する。
- データ保存後、管理者へ新しい問い合わせがあった旨をメールで通知する。
- 必要に応じてLINEなどのメッセージングサービス経由でも管理者へ通知する。
- ユーザーに対しては、問い合わせ受付完了の自動返信メールを送信する。
- データ保存を最優先し、通知処理が失敗した場合はGASのログに詳細を記録する。
- 二重送信防止のため、クライアントサイドまたはGAS側でidempotencyKeyのような仕組みを導入し、重複する送信を識別・防止する。
- 各フォーム送信に対して一意の受付番号を発行し、管理と追跡を容易にする。

## カゾクノカワリ用フォーム項目案

### 基本項目
- 受付日時
- 受付番号
- 受付種別 (例: 依頼、相談、パートナー登録、テスト)
- お名前
- 電話番号
- メールアドレス
- 希望連絡方法 (例: 電話、メール、LINE)
- 希望サービス (複数選択可)
- 訪問エリア (シミュレーターからの選択値)
- 詳しい訪問場所 (自由入力テキスト)
- 訪問場所調整 (シミュレーターからの調整額/テキスト)
- シミュレーター概算 (シミュレーターからの算出値/テキスト)
- オプション (シミュレーターからの選択値)
- 希望内容・相談内容 (自由入力テキスト)
- 購入品の有無 (例: あり/なし)
- 購入予定額・予算上限 (自由入力テキスト)
- 備考 (自由入力テキスト)
- 流入元ページ (hidden: フォームが設置されているページのURLなど)
- ステータス (例: 新規、対応中、完了、キャンセル)
- 対応メモ (管理者記入用)
- 受信JSON (GASで受信した全JSONデータを格納)

### システム項目
- correlationId (リクエストの一貫性追跡用)
- idempotencyKey (二重送信防止用)
- clientVersion (フォームのバージョン情報など)
- userAgent (ユーザーエージェント文字列)
- referrer (リファラーURL)
- 管理者メール送信 (成功/失敗/N/A)
- 自動返信メール送信 (成功/失敗/N/A)
- LINE通知送信 (成功/失敗/N/A)
- エラー内容 (発生したエラーの詳細)

## 実装時の注意点

- 既存HPのGASをそのまま流用せず、カゾクノカワリ専用のGASプロジェクトを新規作成する。
- カゾクノカワリ専用のGoogle Sheetsを新規作成し、上記の列定義案に基づいてシートを準備する。
- GAS Web AppのURLをHTMLに直書きしない、または直書きする場合でも公開リスクを理解した上で、そのリスクを最小化する運用を検討する（例：スクリプトプロパティから読み込む、環境変数で管理するなど）。
- APIキー、Spreadsheet ID、管理者メールアドレス、LINE通知用のトークンなどの秘密情報は、GASのScript Propertiesに設定し、コード内に直書きしない。
- 本番環境への送信テストは、事前に内容を十分に確認し、安全性を確保した上でのみ行う。
- テスト送信は、「受付種別」を「テスト」とするなど、テストデータであることが明確に分かるようにしてGoogle Sheetsに保存する。
- 二重送信防止のため、フォーム送信時にidempotencyKeyを生成し、GAS側で重複チェックを行う仕組みを導入する。
- 送信成功時は `thanks.html` へ遷移させる方式が現在の静的HTML構成に合致しており、まずは `fetch` + `GAS doPost` + `thanks.html` 遷移が現実的な実装アプローチとなる。
